## 1. Назначение модуля

Модуль `input` реализует трансформацию неструктурированного текста в строго типизированное абстрактное синтаксическое дерево (АСТ) и структуру `RawSystem`.

```text
[Текст пользователя] ──► input ──► [RawSystem] ──► polynomization ──► solver
```

**Ключевой принцип:** модуль намеренно изолирован от математической логики. Он не вычисляет производные, не строит полиномы Тейлора и не решает уравнения. Его единственная задача — корректно интерпретировать ввод, проверить базовую согласованность данных и подготовить их для этапа нормализации и полиномизации.

## 2. Входные и выходные данные

### Входные данные
Текстовое представление системы ОДУ. Поддерживается ввод из строки, файла или стандартного потока (`stdin`).

*Пример ввода:*
```text
# Система осциллятора
x'' + sin(x) = y' + t
y'           = x*y - 1
x(0)         = 1
x'(0)        = 0
y(0)         = 0
```

### Выходные данные
Структура `RawSystem`, содержащая «сырое» представление системы точно в том виде, в котором её задал пользователь.

```cpp
struct RawSystem {
    std::string                   independent_variable;  // По умолчанию "t"
    std::vector<std::string>      functions;             // {"x", "y"}
    std::vector<Equation>         equations;             // Деревья lhs и rhs
    std::vector<InitialCondition> initial_conditions;    // Структуры {func, order, t0, value}
};
```
*Примечание:* На этом этапе система **не нормализована**. Уравнения не обязательно разрешены относительно старших производных, а производные могут присутствовать в обеих частях равенства. Приведение к каноническому виду (разрешение относительно старших производных, замена переменных) выполняется на следующих этапах пайплайна.

## 3. Трёхуровневая архитектура

Модуль спроектирован по принципу строгой иерархии с однонаправленными зависимостями. Каждый вышестоящий слой использует нижестоящий, но нижестоящий **ничего не знает** о существовании вышестоящих.

```text
                     ВЫСОКИЙ УРОВЕНЬ (Система целиком)
                            ▲
                            │ использует
            ┌───────────────┴───────────────┐
            │           input               │  ParseSystem, Validate
            └───────────────┬───────────────┘
                            │ использует
                            ▼
            ┌───────────────────────────────┐
            │           parser              │  ParseExpression, ParseEquation
            └───────────────┬───────────────┘
                            │ использует
                            ▼
            ┌───────────────────────────────┐
            │         expression            │  Expr, Make*, ToString
            └───────────────────────────────┘
                     НИЗКИЙ УРОВЕНЬ (Абстрактное дерево)
```

| Слой | Зона ответственности | Изолирован от (ничего не знает про) |
| :--- | :--- | :--- |
| **`expression`** | Структура данных (АСТ), фабрики узлов, обход дерева. | Текст, синтаксис, токены, уравнения, системы. |
| **`parser`** | Синтаксический анализ одной строки, лексический разбор. | Смысл системы, файлы, stdin, семантические противоречия. |
| **`input`** | Сборка системы, классификация строк, семантическая валидация. | Символы, токены, правила грамматики, реализация парсера. |

## 4. Слой `expression`: структура дерева

### Концепция
Математическое выражение (например, `x + y * sin(t)`) представляется не как строка, а как рекурсивная структура данных — дерево.

```text
       (+)
      /   \
    (x)   (*)
         /   \
       (y)  (sin)
              |
             (t)
```

### Типы узлов
Базовый класс `Expr` реализован через `std::variant`, объединяющий шесть типов узлов. Дочерние узлы (в `Binary` и `Call`) хранятся через `std::unique_ptr` (`ExprPtr`) для обеспечения уникальности владения и поддержки рекурсии.

| Тип узла | Описание | Пример в тексте |
| :--- | :--- | :--- |
| `Number` | Числовой литерал (целое, дробное, экспоненциальное). | `2`, `3.14`, `-1e-3` |
| `Function` | Символьное имя переменной или неизвестной функции. | `x`, `y`, `alpha` |
| `Constant` | Именованная константа (из файла или `extra_constants`). | `pi`, `g` |
| `Derivative` | Производная функции по независимой переменной. | `x'`, `y''` |
| `Binary` | Бинарная арифметическая операция (`+`, `-`, `*`, `/`, `^`). | `x + y`, `t^2` |
| `Call` | Вызов математической функции (имя не проверяется парсером). | `sin(t)`, `pow(x, 2)` |

### API слоя
1.  **Фабрики:** `MakeNumber`, `MakeFunction`, `MakeConstant`, `MakeDerivative`, `MakeBinary`, `MakeCall`.
2.  **Запросы (обход дерева):** `IsLeaf`, `HasDerivative`, `MaxDerivativeOrder`, `CollectFunctionNames`, `CollectDifferentiatedNames`, `CollectConstantNames`.
3.  **Сериализация:** `ToString` (форматирование чисел через `std::to_chars` для краткости).

> **Правило создания узлов:**
> Узлы создаются **строго через фабрики**, а не через `braced-init-list` (фигурные скобки), так как `std::initializer_list` требует копирования элементов, что несовместимо с `std::unique_ptr`.
> ```cpp
> // ПРАВИЛЬНО:
> auto e = MakeBinary(Binary::Op::Add, MakeFunction("x"), MakeNumber(2.0));
> ```

## 5. Слой `parser`: синтаксический анализ

### Назначение
Преобразует **одну текстовую строку** в соответствующую структуру (`ExprPtr`, `Equation` или `InitialCondition`).

### Конфигурация (`ParseOptions`)
Парсер настраивается через структуру `ParseOptions`, передаваемую из слоя `input`:
*   `independent_variable`: имя независимой переменной (по умолчанию `"t"`). Критично для валидации нотации Лейбница (в `dy/dt` знаменатель обязан совпадать с этой переменной).
*   `constants_file` и `extra_constants`: позволяют парсеру на лету отличать константы от неизвестных функций.
*   `line_offset`: сдвиг номера строки для корректного формирования сообщений об ошибках при разборе многострочных текстов.

### Внутреннее устройство
1.  **Лексер (Tokenizer):** Разбивает строку на токены (числа, имена, операторы, скобки). Распознаёт производные в трёх нотациях:
    *   Штрихи: `x'`, `x''`
    *   Лейбниц (ASCII): `dy/dt`, `d^2y/dt^2`
    *   Лейбниц (Unicode): `d²y/dt²`
2.  **Парсер (Recursive Descent):** Обходит токены методом рекурсивного спуска согласно грамматике с учётом приоритетов операций (степень `^` > унарные > умножение/деление > сложение/вычитание).
3.  **Обработка унарного минуса:** В AST нет отдельного узла `Neg`. Выражение `-X` транслируется в `Binary{Sub, Number{0}, X}`. Это упрощает структуру дерева, а математическая оптимизация оставляется для этапа полиномизации.

## 6. Слой `input`: сборка и валидация системы

### Алгоритм `ParseSystem`
1.  **Построчное чтение:** Игнорирует пустые строки и комментарии (`#`).
2.  **Классификация строк:**
    *   *Эвристика:* Если левая часть до знака `=` соответствует паттерну `имя [штрихи] ( число )` (например, `x''(0)`), строка классифицируется как **начальное условие** (`ParseInitialCondition`).
    *   В противном случае строка разбирается как **уравнение** (`ParseEquation`).
3.  **Сбор метаданных:** Автоматически формирует список `functions`, извлекая имена функций, встречающихся под знаком производной (в порядке первого появления).
4.  **Валидация:** Вызов `Validate(sys)` для проверки семантической целостности.

### Семантическая валидация (`Validate`)
В отличие от синтаксических проверок парсера, `Validate` проверяет математическую логику системы:
1.  **Независимая переменная:** Не должна быть пустой и не должна совпадать с именами неизвестных функций или констант.
2.  **Полнота функций:** Каждое имя из списка `functions` должно реально встречаться под знаком производной в уравнениях.
3.  **Достаточность начальных условий:** Для каждой функции количество заданных начальных условий должно быть **не меньше** её старшего порядка производной в системе (например, если есть `x''`, должны быть заданы как минимум `x(t0)` и `x'(t0)`).

*Примечание:* `Validate` намеренно **не проверяет** автономность системы, разрешимость относительно старших производных и полиномиальность правых частей — это задачи последующих модулей.

## 7. Сквозной пример обработки

Рассмотрим систему:
```text
x' = -y
y' = x
x(0) = 1
```

1.  **Классификация:**
    *   `x' = -y` ➔ Уравнение.
    *   `y' = x` ➔ Уравнение.
    *   `x(0) = 1` ➔ Начальное условие (паттерн `имя(число)`).
2.  **Синтаксический разбор (AST):**
    *   `x' = -y` ➔ `Equation { lhs: Derivative("x", 1), rhs: Binary(Sub, 0, Function("y")) }`
    *   `x(0) = 1` ➔ `InitialCondition { "x", order: 0, t0: 0.0, value: 1.0 }`
3.  **Формирование `RawSystem`:**
    *   `functions` = `{"x", "y"}` (собрано из `Derivative` узлов).
4.  **Валидация:**
    *   Старший порядок для `x` и `y` равен 1.
    *   Для `x` задано одно условие (`x(0)`). Достаточно.
    *   Для `y` задано ноль условий. **Ошибка:** `InputError` (не хватает начального условия для `y'`).

## 9. Обработка ошибок

Модуль использует строгую типизацию исключений для разделения ошибок ввода и логики:

| Тип исключения | Источник | Описание |
| :--- | :--- | :--- |
| **`ParseError`** | `parser` | **Синтаксическая ошибка.** Невозможно разобрать токен, нарушен баланс скобок, неверный формат числа. Содержит точные координаты (`line`, `column`) и контекст (`expected`, `found`). |
| **`InputError`** | `input` | **Семантическая ошибка или ошибка I/O.** Система противоречива (не хватает начальных условий, конфликт имён) или не удалось открыть файл. |

*Важно:* `ParseSystem` не «проглатывает» синтаксические ошибки. Если в тексте есть невалидная строка, выполнение прерывается с выбросом `ParseError`.

## 10. Потенциал расширяемости

Архитектура модуля спроектирована с учётом будущих модификаций:

*   **Новые математические функции:** Парсер распознаёт *любое* имя перед скобкой как `Call` (например, `bessel_j0(x)`). Добавление поддержки новых функций не требует изменения парсера — оно реализуется на этапе полиномизации.
*   **Новые типы узлов (например, `Integral`):** Потребуется добавить тип в `std::variant` (`expression.h`), обновить методы обхода (`expression.cpp`) и добавить правило в грамматику (`parser.cpp`). Слой `input` изменений не потребует.
*   **Альтернативные форматы ввода (JSON, YAML):** Достаточно реализовать новый адаптер, который будет заполнять структуру `RawSystem`. Весь последующий пайплайн (валидация, полиномизация) продолжит работу без изменений.
*   **Сбор всех ошибок сразу:** Текущая логика прерывается на первой ошибке. Для реализации режима «показать все ошибки» достаточно ввести тип `ParseErrorList` и изменить логику `ParseSystem` на накопление исключений вместо их немедленного проброса.
