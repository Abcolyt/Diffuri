# Универсальный формат заголовочного файла для проекта Ars Magica 5 (ECS)

- Каждый заголовочный файл должен следовать единой структуре, чтобы обеспечить читаемость, удобство сопровождения и быстрый переход на ECS (Flecs).

- Все комментарии должны быть в формате Doxygen (/** ... */ или ///).
- Порядок блоков строго фиксирован

1) Теги
2) Перечисления (Enums) и id обертки
3) Статические данные
4) Компоненты
5) Утилитный namespace (имя выбирается по смыслу, например location_utils, character_utils). Могут быть вложенные пространства имен.

- Каждый блок отделяется разделительной линией // ============================================================================
для визуального удобства.
- Важно 1: Любая функция, реализация (тело) которой находится в заголовочном файле,
должна быть объявлена с ключевым словом inline, если она не является шаблонной или членом класса.
- Важно 2: Шаблонные функции и функции-члены, определённые внутри класса, неявно inline и не требуют явного указания ключевого слова.
Это предотвращает ошибки множественного определения (ODR) при подключении заголовка в несколько единиц трансляции.
- Важно 3: Определение массивов из Tables должно находиться в соответствующем .cpp файле.
- Важно 4: **Соглашение об именовании:** `<module>_utils` — имя утилитного пространства, образованное по правилам из **Naming Conventions**.
- Важно 5: **Соглашение об именовании статических данных:** `<module>_static` — имя пространства для статических описаний и реестров модуля.
- Важно 6: **Чистота заголовка.** Заголовочный файл модуля (.h) не должен содержать сущностей, не попадающих ни в одну из категорий: теги, перечисления, статические данные, компоненты, утилиты. Устаревшие или временные классы, не соответствующие этой структуре (например, legacy-класс Ability), должны быть вынесены в отдельный переходный файл (например, `legacy_ability.h`) и снабжены комментарием `@deprecated` с указанием плана рефакторинга. Это гарантирует, что основной заголовок модуля всегда остаётся чистым и соответствует архитектуре.

## Терминология

Для единообразного понимания в документе используются следующие термины:

| Термин | Определение | Пример |
|--------|-------------|--------|
| **Модуль** | Логическая единица функциональности, представленная одним заголовочным файлом (`.h`). Объединяет связанные теги, перечисления, компоненты и утилиты. Имя модуля совпадает с именем файла без расширения. | `location.h` → модуль `location` |
| **Тег** (Tag) | Пустая структура, используемая как маркер или флаг состояния в ECS. Не содержит данных и **не** обёрнута в пространство имён. | `struct IncapacitatedTag {};` |
| **Перечисление** (Enum) | Тип `enum class`, определяющий набор именованных констант. Используется компонентами и функциями. **Не** обёрнут в пространство имён. | `enum class Weather { Clear, Rain };` |
| **Статические данные (Static Data)** | Пространство имён (или класс), содержащее неизменяемые описания, справочники и реестры сущностей (например, каталог всех возможных навыков, типов урона, языков). Используется для инициализации, валидации и получения эталонных значений динамическими компонентами. Не является компонентом ECS и не привязано к конкретной игровой сущности. | `abilities_static::Abilitys_data` |
| **Динамические данные (Dynamic Data)** | Структуры или компоненты ECS, содержащие изменяемое состояние конкретного экземпляра сущности (персонажа, предмета и т.п.). Ссылаются на статические данные по идентификатору и не дублируют неизменяемые описания. Могут быть как отдельными компонентами ECS, так и вспомогательными контейнерами внутри них. | `SkillInstance`, `components::WoundCounters` |
| **Компонент** (Component) | Структура с данными, представляющая один аспект сущности в ECS. Всегда помещается в пространство имён `components`. | `components::WoundCounters` |
| **Утилиты** (Utils) | Пространство имён `<module>_utils`, содержащее функции для работы с компонентами модуля, а также вложенные подпространства с действиями (`actions`), вычислениями (`calculation`) и т.д. | `wounds_utils::inflict::apply()` |

### Отличие модуля от компонента

Один модуль (файл) может содержать **множество компонентов**, объединённых общей предметной областью.

| Понятие | Пример | Что содержит |
|---------|--------|--------------|
| **Модуль** (файл) | `location.h` | `AuraComponent`, `LocationTypeComponent`, `LocationIdentity`, `LightLevelComponent` и т.д. — **много компонентов**, объединённых темой "локация" |
| **Компонент** | `components::AuraComponent` | Только поля `type` и `rating` — это **один конкретный компонент** ECS |

## Именование вложенных пространств имён (подпространств)

Внутри `<module>_utils` допускается создание произвольного количества вложенных пространств имён.  
Имена подпространств **выбираются разработчиком по смыслу** и должны отражать назначение сгруппированных сущностей.  
**Стиль:** все пространства имён (включая вложенные) — **snake_case**.

Рекомендуемые (но не обязательные) шаблоны имён:

| Имя подпространства       | Назначение | Примеры |
|---------------------------|------------|---------|
| `tables`                  | Константные таблицы данных | `extern const int thresholds[]` |
| `actions`                 | Функции, **изменяющие** состояние компонентов | `void increase(Comp&)` |
| `calculation`             | функции, возвращающие числовые результаты вычислений на основе компонентов (бонусы, модификаторы, пороги), не меняющие изначальные данные | `int get_total(const Comp&)` |
| `info`                    | функции, возвращающие строковые представления или метаданные для отображения (названия, описания, временные метки). | `const char* get_name(Enum)` |
| `predicates`              | Функции-предикаты (`bool`) | `bool is_valid(const Comp&)` |
| `factory`                 | Функции-конструкторы | `MyComponent create_default()` |
| `<component>_modifiers`   | **Специализированные** бонусы/штрафы от конкретного компонента | `aura_modifiers`, `wound_penalties` |


**Рекомендации по выбору имени:**

1. **Семантическая ясность** — имя должно сразу говорить, что делает код внутри.
2. **Единственность ответственности** — не смешивайте в одном подпространстве действия и запросы; лучше разнести их.
3. **Согласованность внутри модуля** — если уже есть `actions`, не создавайте рядом `doers`.
4. **Английский язык** — для единообразия проекта.

*Примечание 1:* Имена подпространств выбираются по смыслу. `<component>_modifiers` — рекомендуемый шаблон для функций, возвращающих модификаторы от определённого компонента.

*Примечание 2:* Допускается **не создавать** подпространства вовсе, если модуль утилит состоит из 2–3 функций. В таком случае функции размещаются непосредственно в `<module>_utils`.



## 1. Теги (Tags)

Пустые структуры, используемые как маркеры или флаги в ECS. Они **не** обёрнуты в пространство имён.

Пример кода:
```cpp
// ============================================================================
// ТЕГИ
// ============================================================================

/**
 * @struct MyFeatureTag
 * @brief Тег: описание, когда этот тег присутствует.
 */
struct MyFeatureTag {};
```

## 2. Перечисления (Enums)

**Важно:** Все перечисления, объявленные в заголовочном файле, считаются частью публичного API модуля.  
Перечисления, используемые **только** внутри реализации (например, в `.cpp` файлах), должны быть определены непосредственно в этих `.cpp` файлах и **не включаться** в заголовок.

*Примечание:* Альтернативный случай (редкий), когда одно и то же локальное перечисление нужно нескольким .cpp файлам одного модуля рассматривается отдельно.

Пример кода:
```cpp
// ============================================================================
// ENUM'ы
// ============================================================================

/**
 * @enum MyEnum
 * @brief Описание перечисления.
 */
enum class MyEnum { Value1, Value2 };
```
:Конец примера кода.

## 3. Статические данные
Статические данные — это неизменяемые описания, справочники и реестры сущностей предметной области. Они не являются ECS-компонентами и не привязаны к конкретным игровым сущностям. Используются для инициализации, валидации и получения эталонных значений динамическими компонентами.

**Соглашение об именовании** : Имя пространства имён для статических данных модуля образуется из имени файла без расширения с добавлением суффикса _static.
Например:

abilities.h → abilities_static

locations.h → locations_static

Внутри пространства имён <module>_static размещаются классы, структуры и константы, содержащие эталонные описания. Например, каталог всех доступных навыков, типов урона, языков и т.п.

Важно: Определения не-inline функций и статических членов данных должны находиться в соответствующем .cpp файле.

Пример кода:
```cpp
// ============================================================================
// СТАТИЧЕСКИЕ ДАННЫЕ
// ============================================================================

namespace abilities_static {

    /**
     * @struct SkillDefinition
     * @brief Структура для описания одного навыка.
     */
    struct SkillDefinition {
        std::string name;
        std::string specialization;
        std::string description;
        AbilityType type;
        AbilitySubtype subtype;
        bool requires_training;
    };

    /**
     * @class Abilitys_data
     * @brief Реестр всех доступных навыков.
     *
     * Хранит эталонные описания навыков, индексированные по ID.
     * Предоставляет методы добавления, поиска и итерации.
     */
    class Abilitys_data {
    public:
        int Add(const SkillDefinition& def);
        const SkillDefinition& GetDefinition(int id) const;
        int FindByName(const std::string& name) const;
        size_t Size() const;

        // ... остальные методы

    private:
        std::vector<SkillDefinition> definitions_;
        std::unordered_map<std::string, int> name_to_id_;
    };

} // namespace abilities_static
```

## 4. Компоненты (namespace components)

Все структуры данных, представляющие компоненты ECS. Они обязательно помещаются в пространство имён components.

Пример кода:
```cpp
// ============================================================================
// КОМПОНЕНТЫ
// ============================================================================

namespace components {

    /**
     * @struct MyComponent
     * @brief Описание компонента.
     */
    struct MyComponent {
        int field = 0;
    };

    // ... остальные компоненты

} // namespace components
```
:Конец примера кода.

## 5. Утилиты / Системные функции (namespace location_utils или аналогичное)

Функции, работающие с компонентами, а также связанные с ними константы и вспомогательные типы.
Они группируются по подпространствам внутри утилитного пространства имён.
Где `<module>` — название предметной области (имя `.h` файла без расширения, в нижнем регистре).

**Соглашение об именовании:** Имя утилитного пространства имён **должно** образовываться
из имени файла без расширения с добавлением суффикса `_utils`.
Например:
- `location.h` → `location_utils`
- `wounds.h` → `wounds_utils`
- `fatigue.h` → `fatigue_utils`

Вложенные пространства имён могут содержать:
- Функции (как свободные, так и `inline`)
- Константные таблицы данных (`extern const int[]`, `extern const char* const[]`)
- Вспомогательные `enum` или `struct`, используемые только внутри утилит

Рекомендуется
- Группировать в пространствах имен по общем признакам, как то: 
1) Являются константными табличными данными любого типа: 
 extern const int recovery_timers[1, 2,3,5,7,11,13...];
2) Используются для работы с одним компонентом:
 namespace aura_modifiers {
 Пример кода:
        /**
         * @brief Бонус ауры для герметической магии.
         * @param aura Аура локации.
         * @return Целочисленный бонус (обычно от -3 до +3).
         */
        int GetMagicBonus(const components::AuraComponent& aura);

        /**
         * @brief Бонус ауры для божественных действий.
         * @param aura Аура локации.
         * @return Целочисленный бонус.
         */
        int GetDivineBonus(const components::AuraComponent& aura);
 :Конец примера кода.


Пример кода:
```cpp
// ============================================================================
// УТИЛИТЫ

namespace wounds_utils {

    /**
     * @brief Группа функций для расчётов на основе компонента.
     */
    namespace calculation {
        /**
         * @brief Вычисляет итоговое значение.
         * @param comp Компонент.
         * @return Итоговое значение.
         */
        int GetTotal(const components::WoundCounters& comp);

         * @brief Возвращает базовое значение (inline).
         * @param comp Компонент.
         * @return Базовое значение.

        inline int GetBase(const components::WoundCounters& comp) { return comp.light; }

    /**
     * @brief Таблицы констант для модуля.

    namespace tables {
        extern const int level_thresholds[];   ///< Пороги уровней

    /**
     * @brief Действия, изменяющие состояние компонента.
     */
    namespace actions {
        /**
         * @brief Увеличивает значение.
         * @param comp Компонент (изменяется).
         */

        /**
         * @brief Сбрасывает значение к начальному.
         * @param comp Компонент (изменяется).
         */
        void Reset(components::WoundCounters& comp);
    }

} // namespace wounds_utils
```
