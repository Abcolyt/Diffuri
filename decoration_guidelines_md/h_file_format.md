# Универсальный формат файлов для проекта Diffuri

Этот документ описывает единый стиль оформления `.h` и `.cpp` файлов проекта **Diffuri** (C++-библиотека численного решения ОДУ методом рядов Тейлора).

**Цели документа:**
- Обеспечить читаемость и единообразие кодовой базы (~50 файлов в `src/`).
- Облегчить сопровождение и code review.
- Сделать математические концепции и ссылки на статью-первоисточник [Бабаджанянц, Большаков 2012] легко находимыми.
- Отделить публичный API от внутренней реализации.

Все комментарии должны быть на **русском языке** и в формате Doxygen (`/** ... */` или `///`). Порядок блоков внутри файла строго фиксирован.

---

## Терминология

Для единообразного понимания в документе используются следующие термины:

| Термин | Определение | Пример |
|--------|-------------|--------|
| **Модуль** | Логическая единица функциональности, представленная парой `.h`/`.cpp` (или одним `.h` для header-only). Имя модуля совпадает с именем файла без расширения. | `solver.h` → модуль `solver` |
| **Публичный API** | Сущности, объявленные в `.h` файле и доступные потребителям модуля. | `Solve()`, `SolveOptions`, `SolverError` |
| **Структура данных** | Структура/класс, хранящий состояние системы или результат вычислений. | `RawSystem`, `Solution`, `Equation` |
| **Опции / Конфигурация** | Структура с параметрами, передаваемыми в функции модуля. | `SolveOptions`, `ParseOptions` |
| **Исключение** | Класс-наследник `std::exception` для ошибок этапа. | `ParseError`, `SolverError`, `InputError` |
| **Статья-первоисточник** | [Бабаджанянц, Большаков 2012] — «Вычислительные методы и программирование», т. 13, с. 497–510. | Ссылки вида `§2.1.4` |

### Математические обозначения (единые по всему проекту)

| Понятие | Как писать в коде / комментариях |
|---|---|
| Порядок метода | `M` (заглавная) |
| Шаг интегрирования | `h` |
| Число доп. членов для оценки остатка | `K` |
| Радиус сходимости | `ρ` (или `rho` в именах переменных) |
| Безразмерный шаг | `τ` (или `tau`) |
| Априорный шаг | `h_a` или `prior_step` |
| Апостериорный шаг | `h_b` или `posterior_step` |
| Масштабирующие множители | `α` или `alpha` |
| Итеративная коррекция | Ссылка на `§2.1.3` статьи |

## 1. Шапка файла (File Header)

**Единый шаблон** для всех `.h` и `.cpp` файлов. Располагается в самом верху файла, до `#pragma once` и `#include`.

### 1.1. Базовый шаблон

```cpp
// ============================================================================
// src/<модуль>/<файл>.h  (или .cpp)
//
// <Одна-две строки: суть модуля и его место в пайплайне.>
//
// Зависимости:
//   <модуль> -> <список модулей> (или "только std" если нет внутренних)
//
// Отвечает за:
//   - <перечень обязанностей>;
//   - <перечень обязанностей>.
//
// Что модуль НЕ делает:
//   - <ограничение ответственности 1>;
//   - <ограничение ответственности 2>.
//
// [Только для .cpp] Структура файла:
//   1. <раздел 1>
//   2. <раздел 2>
//
// Статус реализации / Ссылки на статью:
//   - Реализовано: §X.Y.Z.
//   - Не реализовано / TODO: §X.Y.W.
// ============================================================================
```

### 1.2. Правила оформления шапки

- **Разделитель** — строка из `//` + **ровно 76 знаков `=`**.
- **Путь к файлу** — от корня проекта: `src/solver/solver.h`, а не `solver.h` или `solver/solver.h`.
- **Раздел «Зависимости»** — обязателен. Если модуль не зависит от других модулей проекта, писать `(только std)`.
- **Раздел «Что модуль НЕ делает»** — обязателен для модулей с широкой ответственностью (`solver`, `input`, `parser`). Помогает избежать расползания функциональности.
- **Ссылки на статью** — с номером параграфа: `§2.1.3`. Номер страницы добавляется только при цитировании конкретной формулы или таблицы: `[Бабаджанянц, Большаков 2012, §2.1.3, с. 4]`.
- **Для `.cpp`** добавляется блок **«Структура файла»** — нумерованный список разделов файла. Это навигация для читателя.

### 1.3. Пример шапки для `solver.h`

```cpp
// ============================================================================
// src/solver/solver.h
//
// Модуль solver: оркестрация численного интегрирования полиномиальной
// (квадратичной) системы ОДУ методом рядов Тейлора с адаптивным шагом
// и (опционально) адаптивным порядком.
//
// Зависимости:
//   solver -> input (RawSystem)
//   (внутренние) taylor_spec, taylor_table, error_control,
//                step_control, order_control, convergence
//
// Отвечает за:
//   - публичный API: SolverError, SolveOptions, SolvePoint, Solution, Solve;
//   - главный цикл интегрирования от t_0 до t_end;
//   - владение переменными состояния (t, x, M, h);
//   - градуировку t(p) (§2.1.5) при включённой адаптации.
//
// Что модуль НЕ делает:
//   - не извлекает T/S/a (это taylor_spec);
//   - не вычисляет коэффициенты (это taylor_table);
//   - не оценивает погрешность (это error_control);
//   - не выбирает h/M (это step_control / order_control).
//
// Адаптация порядка (§2.1.5, §2.1.6, §2.3 статьи [Бабаджанянц, Большаков 2012])
// управляется флагом enable_order_adaptation. По умолчанию он выключен
// (поведение MVP: фиксированный порядок).
// ============================================================================
```

### 2.1. Блок «Опции и конфигурация»

Структуры с параметрами, передаваемыми в функции модуля. Все поля имеют значения по умолчанию через *default member initializers*.

```cpp
// ============================================================================
// НАСТРОЙКИ ИНТЕГРИРОВАНИЯ
// ============================================================================

/**
 * @struct SolveOptions
 * @brief Параметры интегрирования, задаваемые пользователем.
 *
 * Все поля имеют значения по умолчанию. Включение адаптивного порядка
 * (§2.1.5–2.3 статьи) — через enable_order_adaptation.
 */
struct SolveOptions {
    double      t_end = 1.0;        ///< Конечная точка интегрирования.
    double      rtol = 1e-10;      ///< Относительная точность.
    double      atol = 1e-12;      ///< Абсолютная точность.
    double      h_init = 1e-3;       ///< Начальный шаг.
    double      h_min = 1e-12;      ///< Нижняя граница шага.
    double      h_max = 1e-1;       ///< Верхняя граница шага.
    std::size_t M = 20;         ///< Порядок метода; 0 = "не задан" (→ 20).
    std::size_t K = 1;          ///< Доп. члены для оценки остатка.
    std::size_t max_steps = 1'000'000;  ///< Лимит шагов.

    // --- Адаптация порядка (§2.1.5, §2.1.6, §2.3) ---
    std::size_t M_min = 5;                    ///< Нижний предел порядка.
    std::size_t M_max = 60;                   ///< Верхний предел порядка.
    double      m_factor = 5.0;               ///< Триггер смены M: |h/H| > m_factor.
    bool        enable_order_adaptation = false; ///< Включить адаптацию M.
};
```

**Правила:**
- Все поля инициализированы. Это защищает от `std::length_error` и UB при случайном создании объекта без явных значений.
- Для каждого поля — `///` комментарий в той же строке.

### 2.2. Блок «Структуры данных»

Структуры/классы, представляющие состояние системы или результат вычислений. Сюда попадают `RawSystem`, `Equation`, `Solution`, `SolvePoint`, AST-узлы (`Expr`, `Binary`, `Unary`).

```cpp
// ============================================================================
// РЕЗУЛЬТАТ
// ============================================================================

/**
 * @struct SolvePoint
 * @brief Одна точка траектории: время t и вектор состояния x(t).
 */
struct SolvePoint {
    double              t = 0.0;
    std::vector<double> x;
};

/**
 * @struct Solution
 * @brief Результат интегрирования.
 *
 * points.front() — начальная точка (t_0, x_0).
 * points.back()  — финальная точка (t_final, x(t_final)).
 * functions      — имена функций системы (в порядке, соответствующем x[k]);
 *                  включает вспомогательные переменные, введённые
 *                  Polynomize и Quadratize.
 */
struct Solution {
    std::vector<SolvePoint>  points;
    std::vector<std::string> functions;
    std::string              independent_variable;
    std::size_t              order_used = 0;
    std::size_t              steps = 0;
    double                   t_final = 0.0;
};
```

### 2.3. Блок «Исключения»

Классы-наследники `std::exception`, специфичные для этапа пайплайна.

```cpp
// ============================================================================
// ОШИБКИ SOLVER
// ============================================================================

/**
 * @class SolverError
 * @brief Ошибка этапа численного интегрирования.
 *
 * Типичные причины:
 *   - t_end <= t_0 (нечего интегрировать);
 *   - не удалось однозначно определить t_0 по начальным условиям;
 *   - превышен лимит шагов (max_steps);
 *   - величина шага опустилась ниже h_min;
 *   - RHS системы содержит моном степени > 2 (система не квадратизирована);
 *   - несовпадение порядка начальных условий с sys.functions.
 */
class SolverError : public std::runtime_error {
public:
    explicit SolverError(const std::string& what);
};
```

### 2.4. Блок «Публичный API»

Свободные функции, составляющие внешний интерфейс модуля.

```cpp
// ============================================================================
// ОСНОВНАЯ ФУНКЦИЯ
// ============================================================================

/**
 * @brief Проинтегрировать систему методом рядов Тейлора.
 *
 * При enable_order_adaptation = false:
 *   - порядок M фиксирован (opts.M или 20 если opts.M == 0);
 *   - шаг h адаптивен (PickStep).
 *
 * При enable_order_adaptation = true:
 *   - выполняется градуировка t(p) для p ∈ [M_min, M_max] (§2.1.5);
 *   - на первом шаге M выбирается по argmax V(p) (§2.1.6);
 *   - на последующих шагах M пересматривается при |h/H| > m_factor (§2.3).
 *
 * Пайплайн-предусловие: система должна быть квадратичной (после Polynomize
 * + Quadratize). Если в RHS встречается моном степени > 2 — SolverError
 * (бросается из taylor_spec).
 *
 * @param sys  Нормализованная и квадратизированная система ОДУ.
 * @param opts Параметры интегрирования (по умолчанию — стандартные).
 * @return     Solution Объект с точками траектории и метаданными.
 * @throws     SolverError при ошибках из описания класса SolverError.
 */
[[nodiscard]] Solution Solve(const RawSystem& sys,
    const SolveOptions& opts = {});
```

```cpp
// ============================================================================
// 1. АНОНИМНЫЙ NAMESPACE: локальные утилиты
// ============================================================================
namespace {
    // вспомогательные функции, константы, типы
} // namespace

// ============================================================================
// 2. РЕАЛИЗАЦИЯ ИСКЛЮЧЕНИЙ

// ============================================================================

```

### 3.2. Правила для `.cpp`

- **Анонимный namespace** — обязателен для всех внутренних вспомогательных функций, констант и типов. Это защищает от ODR-нарушений и делает их невидимыми снаружи.
- **Порядок разделов** — указывается в шапке файла в блоке «Структура файла».
- **Реализация функций-членов** — группируется рядом с объявлением класса (если класс в том же `.cpp`) или в отдельном разделе «Реализация методов <Класс>».
- **Локальные константы** — внутри анонимного namespace, с префиксом `k` или в `UPPER_CASE`:
  ```cpp
  namespace {
      constexpr int kGraduationRuns = 10;
      constexpr double kEpsilon = 1e-12;
  }
  ```

## 4. Соглашение об именовании

Единый стиль, основанный на Modern C++ (LLVM/Google-стиль, адаптированный под проект).

### 4.1. Базовые категории

| Категория | Стиль | Пример |
|-----------|-------|--------|
| Имена файлов | `snake_case` | `solver.h`, `taylor_table.cpp` |
| Классы и структуры | `PascalCase` | `RawSystem`, `SolveOptions`, `Lexer` |
| Пространства имён | `snake_case` | `diffuri`, `step_control` |
| Перечисления (`enum class`) | `PascalCase` | `StdinMode`, `Tok` |
| Значения перечислений | `PascalCase` | `StdinMode::UntilEof`, `Tok::Number` |
| Свободные функции | `PascalCase` + семантический префикс | `ParseSystem()`, `Solve()`, `IsBlankOrComment()` |
| Функции-члены (методы) | `PascalCase` | `parser.Advance()`, `table.Evaluate()` |
| Члены данных (поля) | `snake_case` | `independent_variable`, `h_init` |
| Приватные поля | `snake_case` + суффикс `_` | `text_`, `pos_`, `constants_` |
| Шаблонные параметры | `PascalCase` (осмысленные) или `T`, `U` | `ExprNode`, `T` |
| Константы (глобальные, статические, `constexpr`) | `kPascalCase` или `UPPER_CASE` | `kGraduationRuns`, `MAX_STEPS` |
| Локальные переменные / параметры | `snake_case` | `t_end`, `user_name`, `clean_damage` |
| `using`-алиасы типов | `PascalCase` | `using ExprPtr = std::unique_ptr<Expr>;` |
| Макросы (включая include guards) | `UPPER_CASE` | `DIFFURI_SOLVER_H_` (не используется — применяем `#pragma once`) |

### 4.2. Семантические префиксы для свободных функций

| Категория функции | Рекомендуемый префикс | Примеры |
|-------------------|-----------------------|---------|
| **Действия** (изменяют состояние) | Глагол в повелительном наклонении | `Validate()`, `Reset()`, `NormalizeSystem()` |
| **Запросы / Вычисления** | `Get`, `Calculate`, `Find`, `Collect`, `Derivative` | `CollectT0s()`, `DerivativeOrders()`, `CalculateError()` |
| **Предикаты** (возвращают `bool`) | `Is`, `Has`, `Can`, `Looks` | `IsBlankOrComment()`, `LooksLikeInitialCondition()` |
| **Фабрики / Парсеры** | `Make`, `Parse`, `Build` | `ParseSystem()`, `BuildTaylorSpec()`, `MakeBinary()` |
| **Преобразования** | `To`, `From` | `ToString()`, `FromJson()` |

### 4.3. Запреты

- **Не использовать однобуквенные имена** для локальных переменных, кроме индексов циклов (`i`, `j`, `k`) и шаблонных параметров (`T`, `U`).
- **Не использовать венгерскую нотацию** (`strName`, `iCount`).
- **Избегать сокращений**, кроме общепринятых: `lhs`/`rhs` (left/right-hand side), `pos` (position), `len` (length), `t0`/`t_end`, `h`/`M`/`K` (математические обозначения).

## 5. Doxygen-комментарии

### 5.1. Обязательные сущности

Doxygen-комментарий (`/** ... */`) **обязателен** для:
- Всех публичных классов, структур, перечислений в `.h`.
- Всех публичных свободных функций в `.h`.
- Всех публичных методов классов.
- Всех полей структур (допускается `///` на той же строке).

Doxygen-комментарий **не нужен** для:
- Функций и типов в анонимном namespace внутри `.cpp` (достаточно обычного `//`).
- Приватных методов (достаточно `//` внутри класса).
- Очевидных getter/setter.

### 5.2. Минимальный набор тегов

```cpp
/**
 * @brief Краткое описание — одна строка, что функция делает.
 *
 * <Опционально: подробности, формула, ссылка на статью,
 *  описание ветвления поведения.>
 *
 * @param name  Описание параметра.
 * @param name2 Описание второго параметра.
 * @return      Что возвращается (если не void).
 * @throws      ТипИсключения При каких условиях.
 */
```

### 5.3. Правила

- **`@brief`** — всегда. Одна строка, с заглавной буквы, с точкой в конце.
- **`@param`** — для каждого параметра, даже если имя говорящее.
- **`@return`** — если функция возвращает не `void`.
- **`@throws`** — если функция бросает исключения. Указать тип и условия.
- **Параметры-заглушки** (для совместимости с ТЗ, не используются) помечать явно:
  ```cpp
  @param x Не используется в MVP, оставлен как точка расширения.
  ```
- **Формулы** — в тексте комментария в backtick-блоках или в виде строк:
  ```cpp
  * Формула: h_b = h · (1/ε(h))^{1/(M+1)}.
  ```
- **Ссылки на статью** — с номером параграфа:
  ```cpp
  * Реализация по §2.1.4 статьи [Бабаджанянц, Большаков 2012].
  ```

### 5.4. Пример полного Doxygen-блока

```cpp
/**
 * @brief Проверить семантическую согласованность системы.
 *
 * Проверяет:
 *   - непустоту independent_variable;
 *   - отсутствие конфликтов имён между независимой переменной и функциями;
 *   - достаточность начальных условий для старших порядков производных.
 *
 * НЕ проверяет автономность, разрешимость и полиномиальность — это
 * ответственность последующих этапов пайплайна (Normalize, Polynomize,
 * Quadratize).
 *
 * @param sys Система в «сыром» виде, полученная от парсера.
 * @throws InputError при нарушении любого из условий согласованности.
 *
 * @see ParseSystem, DerivativeOrders, InitialConditionOrders
 */
void Validate(const RawSystem& sys);
```

## 6. Комментарии внутри кода

### 6.1. Разделители блоков

Внутри функций длинные блоки кода разделяются короткими линиями с `// ---`:

```cpp
void ProcessSystem(const RawSystem& sys) {
    // --- 1. Валидация ---
    Validate(sys);
    
    // --- 2. Нормализация ---
    auto normalized = NormalizeSystem(sys);
    
    // --- 3. Полиномизация ---
    auto poly = Polynomize(normalized);
}
```

### 6.2. Объяснения (WHY, а не WHAT)

- ❌ **Плохо:** `// Инкрементируем i` (это видно из кода).
- ✅ **Хорошо:** `// Инкрементируем i ДО доступа к буферу, чтобы избежать off-by-one.`
- ✅ **Хорошо:** `// Используется from_chars вместо stod, т.к. последний учитывает локаль.`

### 6.3. Пометки о техническом долге

```cpp
// TODO: заменить на адаптивный порядок M (§2.1.5 статьи), когда дойдём.
// FIXME: при больших M InverseU вырождается, требует регуляризации.
```

- Без подписи автора (имя устаревает, `git blame` покажет).
- `TODO` — для будущих улучшений.
- `FIXME` — для известных проблем.

### 6.4. Исторические обоснования (Design Rationale) — ХРАНИТЬ ВЕЧНО

```cpp
// Изначально использовался метод Рунге-Кутты 4-го порядка, но для жёстких
// систем (stiff equations) он требовал экстремально мелкого шага, что
// приводило к накоплению ошибки округления. Поэтому перешли на ряды Тейлора
// с адаптивным шагом [Бабаджанянц, Большаков 2012, §2.1].
```

Это самые ценные комментарии — они объясняют **ПОЧЕМУ** код написан именно так.

### 6.5. Мёртвый код

- Заккомментированный C++ код **УДАЛЯТЬ БЕЗ ЖАЛОСТИ**.
- Для истории есть `git blame` и история коммитов.
- Закомментированный код гниет, путает читателя и ломает автодополнение IDE.

## 7. Стиль форматирования

### 7.1. Базовые правила

- **Отступы:** 4 пробела. Табуляция запрещена.
- **Длина строки:** не более 100 символов (Doxygen и URL могут быть длиннее).
- **Скобки:** открывающая на той же строке, что и `if`/`for`/`while`/`функция`:
  ```cpp
  if (x > 0) {
      DoSomething();
  } else {
      DoSomethingElse();
  }
  ```
- **Пробелы вокруг операторов:** `a + b`, `x = y`, `if (x)`.
- **Пробелы после запятых:** `f(a, b, c)`, а не `f(a,b,c)`.

### 7.2. Инклюды

- Группируются в три блока, разделённые пустой строкой:
  1. Соответствующий заголовок (для `.cpp`) — `"solver/solver.h"`.
  2. Стандартная библиотека (по алфавиту).
  3. Внутренние зависимости проекта (по алфавиту).
- Используются угловые скобки `<...>` для стандарта, кавычки `"..."` для проекта.
- **НЕ использовать `using namespace`** в заголовочных файлах.

### 7.3. Namespace

- Весь публичный код — в `namespace diffuri`.
- Внутри `.cpp` — анонимный namespace для вспомогательных сущностей.
- В тестах: `namespace diffuri { namespace { ... } }` — хелперы и `TEST(...)` внутри.
- Без `using namespace` в заголовках.

## 11. Пример: эталонный `solver.h`

```cpp
// ============================================================================
// src/solver/solver.h
//
// Модуль solver: оркестрация численного интегрирования полиномиальной
// (квадратичной) системы ОДУ методом рядов Тейлора с адаптивным шагом
// и (опционально) адаптивным порядком.
//
// Зависимости:
//   solver -> input (RawSystem)
//   (внутренние) taylor_spec, taylor_table, error_control,
//                step_control, order_control, convergence
//
// Отвечает за:
//   - публичный API: SolverError, SolveOptions, SolvePoint, Solution, Solve;
//   - главный цикл интегрирования от t_0 до t_end;
//   - владение переменными состояния (t, x, M, h);
//   - градуировку t(p) (§2.1.5) при включённой адаптации.
//
// Что модуль НЕ делает:
//   - не извлекает T/S/a (это taylor_spec);
//   - не вычисляет коэффициенты (это taylor_table);
//   - не оценивает погрешность (это error_control);
//   - не выбирает h/M (это step_control / order_control).
//
// Адаптация порядка (§2.1.5, §2.1.6, §2.3 статьи [Бабаджанянц, Большаков 2012])
// управляется флагом enable_order_adaptation. По умолчанию он выключен
// (поведение MVP: фиксированный порядок).
// ============================================================================
#pragma once

#include <cstddef>
#include <stdexcept>
#include <string>
#include <vector>

#include "input/input.h"

namespace diffuri {

// ============================================================================
// ОШИБКИ SOLVER
// ============================================================================

/**
 * @class SolverError
 * @brief Ошибка этапа численного интегрирования.
 *
 * Типичные причины:
 *   - t_end <= t_0 (нечего интегрировать);
 *   - не удалось однозначно определить t_0 по начальным условиям;
 *   - превышен лимит шагов (max_steps);
 *   - величина шага опустилась ниже h_min;
 *   - RHS системы содержит моном степени > 2 (система не квадратизирована);
 *   - несовпадение порядка начальных условий с sys.functions.
 */
class SolverError : public std::runtime_error {
public:
    explicit SolverError(const std::string& what);
};

// ============================================================================
// НАСТРОЙКИ ИНТЕГРИРОВАНИЯ
// ============================================================================

/**
 * @struct SolveOptions
 * @brief Параметры интегрирования, задаваемые пользователем.
 *
 * Все поля имеют значения по умолчанию. Включение адаптивного порядка
 * (§2.1.5–2.3 статьи) — через enable_order_adaptation.
 */
struct SolveOptions {
    double      t_end = 1.0;        ///< Конечная точка интегрирования.
    double      rtol = 1e-10;      ///< Относительная точность.
    double      atol = 1e-12;      ///< Абсолютная точность.
    double      h_init = 1e-3;       ///< Начальный шаг.
    double      h_min = 1e-12;      ///< Нижняя граница шага.
    double      h_max = 1e-1;       ///< Верхняя граница шага.
    std::size_t M = 20;             ///< Порядок метода; 0 = "не задан" (→ 20).
    std::size_t K = 1;              ///< Доп. члены для оценки остатка.
    std::size_t max_steps = 1'000'000; ///< Лимит шагов.

    // --- Адаптация порядка (§2.1.5, §2.1.6, §2.3) ---
    std::size_t M_min = 5;                    ///< Нижний предел порядка.
    std::size_t M_max = 60;                   ///< Верхний предел порядка.
    double      m_factor = 5.0;               ///< Триггер смены M: |h/H| > m_factor.
    bool        enable_order_adaptation = false; ///< Включить адаптацию M.
};

// ============================================================================
// РЕЗУЛЬТАТ
// ============================================================================

/**
 * @struct SolvePoint
 * @brief Одна точка траектории: время t и вектор состояния x(t).
 */
struct SolvePoint {
    double              t = 0.0;
    std::vector<double> x;
};

/**
 * @struct Solution
 * @brief Результат интегрирования.
 *
 * points.front() — начальная точка (t_0, x_0).
 * points.back()  — финальная точка (t_final, x(t_final)).
 * functions      — имена функций системы (в порядке, соответствующем x[k]);
 *                  включает вспомогательные переменные, введённые
 *                  Polynomize и Quadratize.
 */
struct Solution {
    std::vector<SolvePoint>  points;
    std::vector<std::string> functions;
    std::string              independent_variable;
    std::size_t              order_used = 0;
    std::size_t              steps = 0;
    double                   t_final = 0.0;
};

// ============================================================================
// ОСНОВНАЯ ФУНКЦИЯ
// ============================================================================

/**
 * @brief Проинтегрировать систему методом рядов Тейлора.
 *
 * При enable_order_adaptation = false:
 *   - порядок M фиксирован (opts.M или 20 если opts.M == 0);
 *   - шаг h адаптивен (PickStep).
 *
 * При enable_order_adaptation = true:
 *   - выполняется градуировка t(p) для p ∈ [M_min, M_max] (§2.1.5);
 *   - на первом шаге M выбирается по argmax V(p) (§2.1.6);
 *   - на последующих шагах M пересматривается при |h/H| > m_factor (§2.3).
 *
 * Пайплайн-предусловие: система должна быть квадратичной (после Polynomize
 * + Quadratize). Если в RHS встречается моном степени > 2 — SolverError
 * (бросается из taylor_spec).
 *
 * @param sys  Нормализованная и квадратизированная система ОДУ.
 * @param opts Параметры интегрирования (по умолчанию — стандартные).
 * @return     Solution Объект с точками траектории и метаданными.
 * @throws     SolverError при ошибках из описания класса SolverError.
 */
[[nodiscard]] Solution Solve(const RawSystem& sys,
    const SolveOptions& opts = {});

} // namespace diffuri
```
