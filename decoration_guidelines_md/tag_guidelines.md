## 🏷️ Tag Guidelines (Правила заполнения поля `tags`)

Поле `tags` в метаданных служит для **семантического поиска** модулей.  
Оно помогает агенту или разработчику быстро находить все файлы, относящиеся к определённой теме, без анализа кода.

### Структура тегов

Рекомендуется использовать **иерархический подход** (от общего к частному).  
Каждый тег — одно слово или словосочетание **в нижнем регистре**, слова разделяются дефисом.

| Уровень                  | Назначение                                     | Примеры                                  |
| ------------------------ | ---------------------------------------------- | ---------------------------------------- |
| **1. Проект / Архитектура** | Обязательные теги для всех файлов проекта       | `ecs`, `ars-magica-5`                    |
| **2. Домен / Слой**       | Крупная подсистема игры                        | `character`, `magic`, `combat`, `world`, `ui` |
| **3. Предметная область**  | Конкретная механика или сущность               | `wounds`, `fatigue`, `aura`, `spell`, `reputation` |
| **4. Тип содержимого** (опционально) | Уточняет характер файла                        | `components`, `tags-ecs`, `utils`, `enums` |

### Правила выбора тегов

1. **Всегда включайте `ars-magica-5`.**  
   Фундаментальный тег, обозначающий принадлежность к проекту.

2. **Включайте `ecs`, если модуль использует ECS-систему.**  
   Так как проект строится на Flecs, этот тег будет присутствовать в большинстве файлов.

3. **Указывайте один основной домен (при необходимости – два).**  
   Выберите доминирующую систему, к которой относится модуль (`character`, `combat`, `magic`, `world`, `ui`).  
   Если модуль равноправно затрагивает две области, допустимо указать обе, но первой идёт более значимая.

4. **Добавляйте 1–2 специфичных тега предметной области.**  
   Это должно быть имя игровой механики (`wounds`, `fatigue`) или ключевого понятия (`aura`, `confidence`).

5. **Опционально указывайте тип содержимого.**  
   Если файл содержит *только* компоненты или *только* перечисления, можно добавить тег `components` или `enums`. Это облегчает поиск всех компонентов по проекту.

6. **Избегайте избыточности.**  
   Не дублируйте информацию из `depends_on` или `title`. Теги не должны перечислять все сущности файла.

7. **Соблюдайте единый формат написания.**  
   - Только **строчные буквы**.  
   - Пробелы заменяются **дефисом**.  
   - Пример: `ars-magica-5`, **не** `Ars_Magica_5` или `ArsMagica5`.

### Примеры

| Модуль                      | Теги                                                         |
| --------------------------- | ------------------------------------------------------------ |
| `wounds.h`                  | `["ecs", "ars-magica-5", "character", "combat", "wounds"]`    |
| `fatigue.h`                 | `["ecs", "ars-magica-5", "character", "fatigue"]`             |
| `type_characteristic.h`     | `["ecs", "ars-magica-5", "character", "characteristics", "components"]` |
| `personality.h`             | `["ecs", "ars-magica-5", "character", "personality", "reputation", "confidence"]` |
| `location/aura.h` (пример)  | `["ecs", "ars-magica-5", "world", "aura", "components"]`      |

### Примечания

- Теги не заменяют описание (`description`), а дополняют его для машинной обработки.
- При добавлении нового модуля сверяйтесь с существующими тегами в других файлах, чтобы избежать дублирования синонимов (например, не используйте `wound` и `wounds` одновременно – выберите один вариант).
- Если вы сомневаетесь, стоит ли добавлять тег, лучше пропустите – короткий список точнее отражает суть, чем раздутый.
